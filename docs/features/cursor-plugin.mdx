An AI editor writing docs without a reference invents things: a component that doesn't exist, a
Font Awesome icon name, a `mint`-style CLI command. Every invention costs you the time to notice
it and the time to undo it.

The Papervine plugin for [Cursor](https://cursor.com) supplies the reference, so the editor is
working from what Papervine actually does.

<Card title="papervine/cursor-plugin" icon="github" href="https://github.com/papervine/cursor-plugin">
  The plugin's source — a skill, writing rules, three commands, and two MCP servers.
</Card>

## Install it

Find **Papervine** in the [Cursor marketplace](https://cursor.com/marketplace) and install it.
A plugin can be installed for your user or scoped to one project; scope it to the project if you
work on several docs sites with different conventions.

  <Card title="The negative space" icon="circle-slash">
    What *doesn't* exist — the frontmatter fields, config keys, and CLI commands a model would

That last one earns its place. Papervine reads the same `docs.json` schema as other platforms,
which is what makes [migrating](/guides/migrate) easy — and also what makes an editor confidently
write a `mode: wide` frontmatter field, or tell you to run `papervine validate`. The plugin names
those explicitly so they don't get written.

## Point it at your own docs

Every Papervine site serves an [MCP endpoint](/features/mcp-servers) at `/mcp` — hosted,
self-hosted, or a running `papervine dev`. Adding your own site gives the editor live search over
the pages you're writing, not just Papervine's.

Add it to `.cursor/mcp.json` in your docs repo:

```json .cursor/mcp.json
{
  "mcpServers": {
    "My Docs": { "type": "http", "url": "https://docs.example.com/mcp" }
  }
}
```

<Tip>
  Use `http://localhost:3000/mcp` against a running [`papervine dev`](/cli) and the editor sees
  your unpublished drafts as you write them.
</Tip>

## Editing and publishing

A Papervine site is a Git repository, so the editor edits files and you publish the way you
already do — a push, or a pull request. Nothing needs to round-trip through a service. **In an
editor, that is the path to prefer**: the change stays in your normal review and commit flow.

The plugin also ships the
[authoring MCP](/features/mcp-servers#authoring-mcp-admin-write), which reads and edits a site
*through Papervine* rather than through your filesystem. Authorize it once in a browser and the
editor holds an expiring token. It earns its place when the repository isn't open — a hosted
site, a quick fix from another machine, an agent working somewhere you aren't.

<Warning>
  Don't edit the same page both ways in one task. A file edit and a draft-branch edit are two
  uncoordinated copies, and whichever publishes last silently wins.
</Warning>

## Other editors

The plugin is packaged in Cursor's format, but the material inside it is plain Markdown — a
`SKILL.md` and six reference files. Any agent that can read a skill directory can use it: clone
the repository and point your tool at `skills/papervine/`.

## Commands

Three, alongside the reference:

| Command | What it does |
|---|---|
| `/papervine-audit` | Sweeps a docs repo for the mistakes that fail silently — unreachable pages, dead nav entries, unresolvable icons, relative links |
| `/papervine-page` | Adds a page, and the `docs.json` entry that makes it reachable |
| `/papervine-migrate` | Reports what a repo from another platform renders unchanged, differently, or not at all |

`/papervine-audit` earns its place because of how the renderer behaves: pages are built never to
break, so a misspelled component is plain text and a page nobody listed is a URL nobody can find.
Neither errors, so neither turns up until a reader does.

## Keeping it accurate

The plugin is its own repository and takes pull requests directly. A structure check runs in its
CI on every push: the manifest has to parse, the logo has to resolve, every rule, command and
skill needs its frontmatter, and the skill's reference index and the files beside it have to
agree in both directions.

If the plugin tells you something Papervine doesn't do,
[open an issue](https://github.com/papervine/cursor-plugin/issues) — that's a bug in the same
sense a broken component is, and a PR is welcome.
